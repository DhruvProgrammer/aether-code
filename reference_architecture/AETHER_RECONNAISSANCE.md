## 1. Current architecture

```
packages/app (TS UI: invoke + listen only)
        │ Tauri IPC (44 commands, 5 wire events, minimal ACL)
crates/aether-desktop (in-process run_task on dedicated thread+runtime)
        │
crates/aether-cli::run_task::run()  ← canonical composition (CLI + desktop share it)
        ├── aether-gateway (explicit per-role bindings, NO routing/fallback)
        ├── aether-runtime (PluginHost, tool seam, scoped restrict, bus)
        ├── aether-core (Agent::run 1295-line loop + Executor tool loop + TaskStateMachine)
        ├── aether-context (estimation, SessionCompactor, checkpoints, budget)
        ├── aether-tools (Tool trait, registry, LocalWorkspace, git, MCP, plugins)
        ├── aether-sessions (SQLite store + snapshots) + aether-workspace + aether-changes
        ├── aether-mind (memory) + aether-skills (budgeted prompt compiler)
        ├── aether-permissions (6-layer engine) + aether-evidence + aether-analysis
        └── aether-models (OpenAI-compatible client) + aether-config + aether-registry
```

No subprocesses (desktop embeds `run_task` in-process). `SessionStore: Connection: !Sync` forces `new_current_thread` runtimes.

## 3. Runtime flow (happy path)

`run_task::run()`: config → gateway (explicit bindings) → context window → Mind/skills → PluginHost boot (7 tool rows) → sessions → engines → `Agent::new(...).with_*()` → `agent.run(task, mode, plan, resume)`.
`Agent::run`: prefetch memory → persist user msg → session_start hooks → TaskStateMachine(CREATED) → skill-compiled coder prompt → LoopEngine → UNDERSTANDING → optional explorer → verification targets → build loop-invariant coder Executor → `for iter in 0..loop_budget`: UNDERSTANDING→PLANNING (LLM2 plan) → PLAN_READY→EXECUTING/REPAIRING (`coder.run`) → REVIEWING (reviewer/tester subagents + EvidenceBag) → VERIFYING (Reviewer concludes) → COMPLETED or REPLANNING; doom/LoopEngine gates → persist assistant msg + record_run + memory sync → optional visual loop → AgentOutcome.

## 4. Agent loop / context flow / provider-model flow / tool flow / session flow / persistence

- **Loop:** plan→execute→verify→(re)plan budget loop; cancellation at iteration boundary only; `resolve()` maps executor→providers[executor_model] else controller clone (silent degradation — see §7).
- **Context:** hot path `preflight_compact` uses coarse chars/4 estimate; auto-compact at ≥70% window; overflow string-match → compact+retry once; checkpoint (20 fields, paths-not-files) generated by LLM2 temp 0.0, validated, saved-before-rebuild, dynamic tail (floor 4); manual trigger exists only via desktop `compact_session` (+ `/compact` slash in UI calling it). No CLI/TUI manual path.
- **Provider/model:** single `openai_compatible` client; model id substituted from config into body (never headers); Bearer/ApiKey/None auth; per-role 180s timeout + cancel; live `validate_binding` ping + FNV fingerprints gating Save/Activate.
- **Tools:** seam pipeline visibility→pre→policy→guard→body→post→persist→result; role allowlists; sandbox + git guards + redaction. **No timeouts, no mid-call cancel** (unbounded `Command.output().await`, MCP `recv()` loop, git).
- **Sessions:** per-sid rows/parts/kv/traces; resume reloads plan + engineering JSON only (transcript NOT rehydrated); `task_state` kv snapshots; snapshots manual-only; no schema-version table.

## 5. Weaknesses (long-running blockers, evidence-backed)

1. No tool timeout/cancel — one hung shell/MCP call hangs the task (`tools/lib.rs:304-308`, `mcp.rs:107-124`, `executor.rs:167`).
2. Resume loses conversation (`run_task.rs:398-401`, `agent_loop.rs:402-409`, executor always fresh `[system,user]`).
3. `ContextManager`/`ContextWorkspace`/`Budget` plumbed but dead (accessors only; zero non-test `budget::build` callers).
4. Snapshot triggers (`PreDanger/PreCompaction/…`) never auto-fire; `truncate_after`/`recovery_state` unwired.
5. `task-state` rich events stringified then only `console.debug`'d — no progress/verification/compaction UI.
6. Permission Ask blocks Tokio worker; non-TTY bash fail-open (`executor.rs:578-596`).
7. TUI/CLI/Desktop composition drift (TUI: no host/scope/compactor/engine/skills/cancel).
8. CI runs zero tests; `aether-cli` has 0 tests.
9. Silent executor→controller fallback in `resolve()` violates explicit-binding spirit.
10. Workspace reads load whole files; no glob; literal-only unranked search.

## 8. Migration risks

- `Connection: !Sync` — keep current-thread runtime; decomposition must not require Send agents.
- Triple composition (desktop/CLI/TUI) — unify, don't fork; TUI is the drift risk.
- `decide_permission` sync-stdin in async context — replace with channel-based approval, keep TTY behavior.
- Silent `resolve()` fallback — remove only with explicit NotConfigured surfacing (desktop already handles Exit{2}).
- No-fallback invariant + 45 gateway tests + no-routing tests must stay green throughout.
- Stale docs (`docs/`, old gap/plan) — this file + Wave 0 rewrites are authoritative; git history preserves prior versions.
